# GM-005

C# 콘솔 프로그램 두 개로 구성된 과제. `switch` 중심의 조건문 연습.

| 폴더 | 내용 | 상태 |

| [01-days-in-month](01-days-in-month) | 일수 출력기 | 완료 |

## 빌드 · 실행

.NET 9 SDK + Visual Studio 2022. `GM-005.sln`을 VS에서 열면 두 프로젝트가 함께 로드된다.

```powershell
dotnet build GM-005.sln

dotnet run --project 01-days-in-month
dotnet run --project 02-rock-paper-scissors        # 시드 지정: -- 1
```

> 과제를 처음 풀 때는 이 PC에 .NET SDK가 없어(VS에 .NET 데스크톱 개발 워크로드 미설치) 콘솔 앱 프로젝트를 만들 수 없었고, VS에 딸린 Roslyn `csc.exe`를 직접 호출해 빌드했다. 이후 워크로드를 설치해 표준 프로젝트로 전환했다. 두 방식의 실행 결과는 동일하다.

## 01 일수 출력기

월 번호를 입력하면 그 달의 일수를 출력한다.

- `1`~`12` → `N월은 XX일까지 있습니다.` 출력 후 재입력
- 범위 밖 숫자 / 숫자가 아닌 입력 → 안내만 출력하고 **입력 횟수에 넣지 않음**
- 유효한 입력 **3번**을 채우면 종료
- 2월은 28일 고정 (윤년 계산 없음)

**구현** — 월별 일수는 `switch`의 case 묶음으로 처리했다. 31일인 달 7개와 30일인 달 4개를 각각 한 덩어리로 묶으면 `if` 체인보다 중복 없이 짧고, 분기 대상이 정수 하나뿐이라 `switch`가 자연스럽다. 1~12가 아니면 `0`을 반환해 호출부에서 예외처리한다.

**확인한 것**

| 입력 | 결과 |
|---|---|
| `1,3,5,7,8,10,12` | 31일 |
| `4,6,9,11` | 30일 |
| `2` | 28일 |
| `0`, `13`, `-5` | 존재하지 않는 월 안내, 카운트 증가 없음 |
| `abc` | 숫자 아님 안내, 카운트 증가 없음 |

1~12월 합계가 365일로 맞는 것까지 확인했다. → `01-days-in-month/screenshots/run-01-validation.txt`

## 02 가위바위보 (배팅)

가위바위보로 소지금을 걸고 최대 5판을 진행한다.

- 초기 소지금 **10,000원**, 최소 배팅 **1,000원**
- 판마다 배팅 금액 → 손(가위/바위/보) 입력
- 정산: **승리 = 판돈 x3 획득 / 무승부 = 판돈 x5 획득 / 패배 = 판돈 x7 손실**
- **5판을 마치거나 소지금이 0원이 되면 종료**
- `q` 입력으로 중단

**구현**

- 기본 골격은 `switch` — 승패 정산, 손 입력 분기, 손 이름 변환 세 곳
- 손과 승패는 `enum Hand` / `enum Result`로 두어 정산 `switch`에서 케이스 누락이 눈에 보이게 함
- 배팅 검증: 최소 금액 미달 / 숫자 아님 / 소지금 초과 → 재입력
- 패배 손실이 소지금보다 클 때는 소지금만큼만 차감 (음수 방지)
- 실행 인자로 시드를 주면 같은 결과 재현 — `.\rps.exe 1`

**치트 기능은 구현하지 않았다.** 요구사항에 기능 이름만 있고 동작 정의가 없어, 임의로 만들면 의도와 다른 결과가 나올 수 있다고 판단했다. 사유는 리뷰에 기록했다.

**확인한 것**

| 시나리오 | 로그 |
|---|---|
| 5판 완주, 승·패·무 정산 | `02-rock-paper-scissors/screenshots/run-01-five-rounds.txt` |
| 전액 배팅 후 패배 → 소지금 0원 종료 | `.../run-02-bankrupt.txt` |
| 배팅 3종 검증(미달/문자/초과), 손 입력 오류 | `.../run-03-validation.txt` |
