# GM-024

Unity 과제 1) 상태 전이 구조 변경: 왼쪽 위 큐브가 맞혀야 할 색(항상 R → G → B 순서)을 보여 주고, 아래 큐브 3개(랜덤 R / G / B)에서 그 색인 큐브의 번호(1 / 2 / 3)를 누른다. B까지 맞히면 1점 + R로, 틀리면 바로 R로.

| 폴더 | 내용 | 상태 |
|---|---|---|
| [01-rgb-order](01-rgb-order) | `ColorOrderGame.cs`: 단계 전이(R → G → B → 1점) · 아래 큐브 랜덤 색 · 오답 초기화 | 완료 |

## 열기 · 실행

Unity `6000.3.9f1`. GM-023 프로젝트(Universal 3D 템플릿, Active Input Handling `Both`)를 복사해 스크립트와 씬 오브젝트만 바꿨다.

1. Unity Hub → **Add project from disk** → `01-rgb-order` 선택
2. `Assets/Scenes/SampleScene` 열기 (`ColorOrderGame` 오브젝트에 `TargetCube` · `ChoiceCube1~3` 연결됨)
3. Play → Game 뷰를 클릭해 포커스 → 왼쪽 위 큐브와 같은 색인 아래 큐브의 번호를 누름

| 키 | 동작 |
|---|---|
| 1 / 2 / 3 | 아래 1 / 2 / 3번 큐브 선택 |

맞힐 색 · 아래 큐브 색 · 점수 · 오답 안내는 Console 로그로 나온다.

## 확인 로그

Unity 과제라 단위 테스트는 붙이지 않았다. Unity 배치 모드에서 임시 에디터 스크립트로 씬을 구성하고, `Press(번호)`를 직접 호출해 단계 · 아래 큐브 색 · 점수를 파일로 남겼다. 무작위는 `Random.InitState(seed)`로 고정했다. 임시 스크립트는 커밋하지 않았다.

각 줄은 키를 누른 **뒤**의 상태다 (아래 큐브는 누를 때마다 다시 뽑으므로, 무엇을 골랐는지는 바로 윗줄의 큐브 색으로 본다).

| 파일 | 내용 |
|---|---|
| `run-00-scene.txt` | 씬 구성과 화면 위치: 목표 큐브는 왼쪽 위(16:9에서 x 0.18 · y 0.85), 아래 큐브 3개 + 번호 1 / 2 / 3 |
| `run-01-correct-flow.txt` | 정답만 골라 R → G → B 두 바퀴: B마다 1점, 왼쪽 위 색이 R로 돌아감 |

## 01 R → G → B

### `ColorOrderGame.cs`

- 단계 `enum Stage { R, G, B }`. `Press(index)`에서 `switch (stage)`로 전이: 맞으면 R → G → B, B면 `score++` 후 R / 틀리면 어느 단계든 R
- 왼쪽 위 `targetCube` 색 = 현재 단계 색, 아래 `choiceCubes[0~2]` 색 = `choices[0~2]`
- `RollChoices()`: 3개를 `Random.Range(0, 3)`으로 따로 뽑고(중복 허용, 그림의 R · G · R처럼), 맞힐 색이 하나도 없으면 `do-while`로 다시 뽑는다
- `Update()`: 1 / 2 / 3 `Input.GetKeyDown` → `Press(0 / 1 / 2)`

**명세에 없거나 해석해서 정한 것**

| 항목 | 정한 내용 |
|---|---|
| 아래 큐브 색을 다시 뽑는 시점 | 정의 없음 → **키를 누를 때마다**(맞든 틀리든) 3개 모두 다시 뽑는다 (사용자 결정). 한 번만 뽑으면 외워서 끝난다 |
| 맞힐 색이 아래에 없을 때 | 그림처럼 중복을 허용하면 약 30%는 맞힐 색이 없어 무조건 틀린다 → **맞힐 색이 1개 이상 나올 때까지 다시 뽑는다** (사용자 결정) |
| "랜덤한 RGB 색상" | 아무 RGB 값이 아니라 R / G / B 세 색 중 하나로 봤다 (그림의 큐브가 빨강 · 초록뿐이고 목표가 R / G / B) |
| 점수 표시 | "1점 획득"만 있고 어디에 보여 주는지 없음 → Console 로그만 |
| 1 / 2 / 3 번호 표시 | 그림에 있어 큐브 위에 `TextMesh` 숫자를 둠 |
| 끝 · 재시작 | 정의 없음 → 없음 (계속 점수를 쌓는다) |
| 과제 제목 "상태 전이 구조 변경" | 무엇에서 바꾸는지 없음 → 단계 enum + `switch` 전이로 구현 |
