# GM-020

C# 콘솔 과제: 판타지 마을 번영도 시스템 (상속 · 추상 클래스 · 오버라이드 · `Building[,]` 2차원 배열).

| 폴더 | 내용 | 상태 |
|---|---|---|
| [01-village-prosperity](01-village-prosperity) | `Building`을 상속한 집 · 시장 · 공원이 주변 배치를 보고 자기 번영도를 계산하고, 마을 관리자는 5x5 배열을 2중 반복문으로 돌며 합산한다 | 완료 |

## 빌드 · 실행

.NET 9 SDK와 Visual Studio 2022를 쓴다. `GM-020.sln`을 VS에서 열면 된다.

```powershell
dotnet build GM-020.sln
dotnet run --project 01-village-prosperity
```

## 테스트

```powershell
dotnet test GM-020.sln
```

테스트 **49개가 모두 통과**한다. 결과는 `screenshots/dotnet-test.txt`에 있다.

**명세 결함을 테스트로 고정해 두었다.**

- `명세결함_인자_없는_GetDailyProsperity로는_같은_건물이라도_칸마다_값이_달라_위치를_넘겨야_한다`: 1단계는 "자신의 위치와 마을 전체 그리드를 보고 계산하는 함수"를 요구하는데, 최종 목표 · 제출 조건은 `GetDailyProsperity()`를 인자 없이 쓴다. 배열 칸에 들어간 객체는 자기 위치도 마을도 모르므로, 같은 집 객체도 칸에 따라 값이 달라진다 (같은 집이 `[0,0]`이면 20, `[4,4]`면 10). 그래서 `GetDailyProsperity(village, row, col)`로 위치와 그리드를 넘긴다.

## 01 마을 번영도

프로그램은 입력 없이 두 마을을 계산해 출력한다.

1. **명세 예시 마을**: 명세 4단계 배치 그대로 (`[0,0]` 집 · `[0,1]` 시장 · `[1,1]` 공원). 총 번영도 60.
2. **예시 마을**: 규칙이 모두 한 번 이상 쓰이도록 12채를 배치. 총 번영도 325.

```
H H M . .
H P H . .
. H M H .
. . . . M
P . . . H
```

각 마을마다 지도, 건물별 `기본 → 최종` 번영도, 총 번영도를 출력한다.

**명세에 없거나 해석해서 정한 것**

| 항목 | 정한 내용 |
|---|---|
| 계산 함수 모양 | `GetDailyProsperity(Building[,] village, int row, int col)`. 명세의 인자 없는 `GetDailyProsperity()`로는 위치를 알 수 없어 인자로 받는다 (위 명세 결함 참고). 건물에 위치를 저장하는 방식은 배열과 위치가 어긋날 수 있어 쓰지 않았다 |
| 부모 클래스 | `abstract class Building` + `abstract GetDailyProsperity`. 자식이 계산을 빠뜨리면 컴파일이 안 된다 |
| 시장 물류 보너스 | 같은 행 · 열의 **어디에든** 다른 시장이 있으면 적용 (인접 여부 · 사이의 건물은 따지지 않음). 행 · 열 둘 다 해당해도 기본은 35 한 번 |
| 공원 경관 보너스 | 공원이 남에게 점수를 넣어 주지 않고, 집 · 시장이 자기 계산에서 8방향의 공원을 세어 +5씩 더한다 ("각 객체가 자기 계산을 스스로") |
| 공원 옆 공원 | 공원은 항상 0이므로 공원끼리는 보너스가 없다 |
| 배치 · 입력 | 명세에 배치 입력 방법이 없어 코드에서 배치한다. 메뉴 · 건물 추가 입력은 만들지 않았다 |
| 지도 기호 | `H` 집 · `M` 시장 · `P` 공원 · `.` 빈 칸 (출력용으로 `Building.Symbol` 추가) |

**구현**

| 파일 | 내용 |
|---|---|
| `Building.cs` | 이름 · 기본 번영도 · 기호, 추상 계산 함수, 자식이 쓰는 공통 도우미 `CountAround4<T>` · `CountAround8<T>` · `AnyInSameLine<T>` (마을 밖 칸은 건너뜀) |
| `House.cs` · `Market.cs` · `Park.cs` | 명세 3단계 계산 순서를 주석 번호 그대로 따라 구현 |
| `Village.cs` | `TotalProsperity`: 2중 `for`로 전체를 돌며 `null`이 아닌 칸의 `GetDailyProsperity`를 더한다. 건물 종류를 묻는 `if` / `switch`가 없다. 예시 마을 두 개 생성 |
| `Program.cs` | 지도 · 건물별 번영도 · 총 번영도 출력 |
