.NET 9 SDK + Visual Studio 2022. `GM-009.sln`을 VS에서 열면 된다.

```powershell
dotnet build GM-009.sln
dotnet run --project 01-lotto          # 시드 지정: -- 7
```

## 테스트

규칙(입력 검사 · 추첨 · 판정)은 `Lotto.cs`에 따로 두고, `Program.cs`는 입출력과 흐름 제어만 맡는다.

```powershell
dotnet test GM-009.sln
```

**35개 전부 통과**. 결과는 `screenshots/dotnet-test.txt`에 있다.

| 대상 | 확인 내용 |
|---|---|
| 입력 검사 | 1·45 경계 통과, 0·46·음수 거부, 문자·빈 값·소수·`1 2` 거부, 이미 고른 숫자 거부 |
| 추첨 | 자동 6개 서로 다름 · 범위 안 (시드 1,000개), 당첨번호 정렬 · 보너스가 당첨번호와 안 겹침, 1~45 전부 나옴 |
| 판정 | 6개 → 1등, 5개 + 보너스 → 2등, 5개 → 3등, 4개 → 4등, 3개 → 5등, 2개 이하 → 낙첨, 입력 순서 무관 |
| 보너스 | 4개 + 보너스는 4등, 3개 + 보너스는 5등 (보너스는 2등에서만 쓰임) |

**명세 결함을 테스트로 고정해 두었다.**

- `명세결함_보너스가_당첨번호와_겹치면_5개만_맞아도_2등이_된다`: 명세에 "보너스는 당첨번호와 다른 숫자" 규칙이 없다. 겹치게 뽑으면 5개만 맞았는데(그중 하나가 보너스와 같은 숫자) 2등이 된다.
- `명세결함_자동번호에_중복을_허용하면_한_숫자가_두_번_맞는다`: "중복 숫자 입력 x"는 사용자 입력 규칙이다. 자동 버전과 추첨에는 중복 규칙이 없어서, 허용하면 `1 1 1`이 3개 일치로 세어져 5등이 된다.

## 01 로또 당첨기

- 시작하면 `1. 사용자 입력 / 2. 자동 중에 1개를 선택하십시오` → 1 또는 2.
- **사용자 입력**: 6개를 한 개씩 받는다. 숫자 아님 / 1~45 밖 / 이미 고른 숫자면 이유를 알려 주고 그 칸만 다시 받는다.
- **자동**: 1~45에서 서로 다른 6개를 뽑는다.
- 그다음 컴퓨터가 **당첨번호 6개 + 보너스 1개**를 뽑는다 (7개를 한 번에 뽑아 겹치지 않게).
- 내 번호 · 당첨번호 · 일치한 숫자 · 등수를 출력하고 끝난다.

**명세에 없어서 정한 것**

| 항목 | 정한 내용 |
|---|---|
| 당첨번호는 누가 정하나 | 컴퓨터가 무작위로 추첨. "2가지 버전"은 내 번호를 고르는 방식으로 봤다 |
| 보너스 번호 | 당첨번호 6개와 다른 숫자 |
| 입력 방식 | 한 줄에 하나씩. 잘못된 값이면 그 칸만 다시 입력 (처음부터 다시 받지 않음) |
| 자동 번호의 중복 | 허용 안 함 (입력 규칙과 같게) |
| 메뉴에서 1·2 외 입력 | 다시 입력받음 |
| 보너스와 4·5등 | 보너스는 2등 판정에만 쓴다. 4개 + 보너스는 4등 |
| 2개 이하 일치 | `낙첨` 출력 |
| 출력 | 번호는 오름차순 정렬, 일치한 숫자를 같이 표시 |
| 몇 번 하나 | 한 번 추첨하고 끝남 |
| 당첨금 | 명세에 없어서 넣지 않음 |

**구현**

- 입력 오류는 `enum InputError { None, NotNumber, OutOfRange, Duplicate }`, 문구와 등수는 `switch`로 나눈다.
- 추첨은 1~45 배열을 Fisher-Yates로 앞에서부터 섞어 필요한 개수만 꺼낸다.
- 실행 로그: `01-lotto/screenshots/` (입력 오류 + 낙첨, 1등, 2등, 3등, 자동 낙첨 · 5등 · 4등).
